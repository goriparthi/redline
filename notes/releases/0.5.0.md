A range picker that actually changes the range, and the update channel is now a menu item.

### Fixed: picking 30 days still drew 14 days

The dashboard said "Scanning 30 days", scanned 30 days, and then charted two weeks. RedLine
caches each Claude transcript it has already parsed, keyed on the file's timestamp and size,
and a parse throws away entries older than the window it was asked for. Every transcript
touched in the last two weeks answered the wider scan from a cache that had already been
trimmed to 14 days, so the only files that came back with a full month were the ones nobody
had opened recently. The window is now part of what makes a cached parse reusable, and a
cache built for a wider range can no longer inflate a narrower one.

The same click had a second, shorter tell: the 14 day scan still running underneath published
its results and cleared the spinner, so old data presented itself as the answer to the new
range. A scan you have already moved past is now dropped instead.

### Added: the update channel is in the menu

**Settings ▸ Updates** now holds both update settings: **Check Daily**, and **Stable
Releases** or **Beta Releases**. Picking a channel rechecks straight away, so it answers with
the build it found rather than waiting for tomorrow's poll. Choosing the channel used to mean
hand-editing `~/.config/redline/config.json`, which is not a setting anyone would find.

### Changed: releases have to earn their way to stable

`scripts/release.sh` will not cut an unbounded run of betas any more. After 3 prereleases on
one version, or 14 days since the first of them, the next release has to be the promotion, and
a stable release for a version that never saw a beta is refused the other way. Release notes
lost their escape hatch in the same pass: there is no longer a path to a release whose body is
a list of commits.
