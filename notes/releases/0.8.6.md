Tools that read RedLine through its command line no longer set off a macOS privacy prompt every minute.

### Fixed: `redline status` asked other apps for access to your data

When another app, such as a dashboard polling `redline status --json`, ran the command line, RedLine looked for its snapshot inside its App Group container before the plain file it always writes under `~/.local/share/redline`. macOS counts that container as RedLine's private data and blames whichever app launched the command, so the caller got a "would like to access data from other apps" prompt, again on every poll. The command line now reads the shared file first and only falls back to the App Group when nothing else has a snapshot, so callers stay out of RedLine's container entirely. The widget still reads its own container first and is unchanged.

### Install

    brew install --cask ./Casks/redline.rb

Or download the DMG below. Requires macOS Sonoma or later. Nothing changed since
0.8.6-beta.1, so if you are already on that build this is the same app with a stable
version number.
