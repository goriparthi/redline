RedLine now answers what your agents are doing as well as what they cost, and it keeps its own history in a real store so each transcript is read once instead of on every poll.

### Added: the agent fleet

Claude Code keeps a live registry of the sessions running on your Mac, one small record per
session, deleted when the session exits. RedLine reads it and lists those sessions in the
dropdown under **Agents**, between the rate limits and the volume: session name, the folder it
is working in, its status, and how long it has been in that status.

The rows sort waiting first, then busy, then idle, and inside each state the one that has been
there longest floats to the top. So the session that has been sitting on a prompt for an hour
is the first line you read. When any session is waiting, an amber dot appears ahead of the
menu bar readout, counted once there is more than one. Busy never earns a badge; a badge that
is always lit says nothing.

Clicking a row goes to the tab that session is running in. A record names the app but not the
window, so RedLine reads the process's controlling terminal from the kernel and matches it
against the tty that iTerm2 and Terminal publish for every tab. Split panes work too. macOS
asks once for permission to control your terminal; decline it and the row still brings the
right app forward, which is also what happens in Ghostty, WezTerm and Alacritty, since those
expose no way to say where a session is. The menu item says which of the two it will do rather
than promising a tab it cannot reach.

Each row also offers the folder path and **Open in claude.ai**, which is the only link between
the local session and its cloud view that Claude Code hands out.

Because the desktop app and the IDE extensions run the same binary, they register in the same
place, so this covers those sessions too. Cloud sessions and sessions on other machines are
deliberately out; there is no public API for them. Nothing here writes to `~/.claude`, and the
key files sitting beside the records are never opened. Switch the whole pane off under
**Settings ▸ Show Running Agents**.

### Changed: the history store is now SQLite

Recorded history was two JSONL files. It is now one SQLite database at
`~/.local/share/redline/history/redline.db`, on the `libsqlite3` macOS already ships, so
nothing was added to the download. Your existing files are imported the first time this
version opens them and are left on disk with a `.migrated` suffix rather than deleted.

There are four tables. `entries` holds one row per usage record, which is new: history used to
start at the daily rollup, and questions finer than a day could only be answered from
transcripts that may already be gone. `daily` is that rollup and is still kept forever.
`limit_samples` holds every limit reading. `ingest_state` records how far into each transcript
has been read. Any SQLite client can open the file, so a question this app does not answer is
now one you can ask yourself.

### Changed: each transcript is read once

RedLine used to reparse the whole lookback window on every poll. On one real machine that was
1,046 files and 880 MB, five minutes apart, with a second copy of the same work whenever the
dashboard opened. It now records the byte offset it stopped at and reads only what has been
appended since, so a quiet poll costs a directory walk.

Three details make that safe rather than merely quick. A half-written trailing line is left
alone until it is complete, because a transcript being written right now ends mid record. A
file that has been truncated or rewritten shorter is read again from the start, because the
offsets no longer point where they did. And records that carry no id of their own, which is
Codex and Ollama, are deduplicated on the position they were read from, while Claude's own
message id still wins where it exists.

One consequence worth knowing: the dashboard now draws from the store rather than from the
transcripts, so its ranges are no longer capped at whatever Claude Code has not pruned yet.

### Fixed: Codex percentages no longer vanish with an old session file

Codex writes its rate limits inside the same events as its token counts, so a poll that read
no new lines had no percentages to show, and a pruned session file took the last known ones
away for good. The stored readings now answer that: the newest one stands, with the time it
was taken, and it is still discarded once its window has rolled over.

### Added: cadence, off until you ask for it

**Settings ▸ Say How the Day Is Going** reports three things counted from timestamps: a run of
activity that has passed 90 minutes with no break longer than fifteen, activity still going
after 23:00, and seven consecutive days with usage. Each is said once at its threshold and
again only at multiples of it, and every number is configurable.

It stays descriptive on purpose. RedLine can see the keyboard and cannot see the person at it,
so nothing here infers tiredness or wellbeing and nothing here offers advice; a cue states what
was counted and stops. A cue can only fire when there is recent activity, so a machine nobody
is using is silent without needing a quiet hours setting. The dashboard draws the hour of day
shape, the current and longest runs and the day count alongside.

### Added: two commands, and a way to run against a different home

`redline ingest` reads new transcript records into the store on demand, for a backfill after
installing or for a machine where the app is not running. `redline cadence` answers the same
questions the panel does, with `--json`.

`REDLINE_HOME` points every path RedLine reads and writes at another directory, honoured only
when it names an absolute path that already exists. It is what lets the tests drive the real
binary without seeing your own data, and it makes a second profile possible without a second
account.

### Changed: the tests, CI, and how a release is cut

There are now 262 unit tests plus an end to end suite that writes fixture transcripts into a
throwaway home, runs the built binary against them and asserts on its output and exit codes.
It found a real bug on its first run, where `status` reported the machine's own percentages
while pointed at an empty test home. CI is `scripts/ci.sh`, and the workflow only decides when
to call it, so everything CI does runs identically on a laptop with `make ci`.

Releasing is written down in `docs/DEPLOY.md`, including the promotion gate that stops a core
version living on beta forever. A DMG sitting in `dist/` is a build nobody can install, so the
packaging script now says so on every exit path. `scripts/bundle.sh` also signs with the same
entitlements file the Xcode path uses; the two build paths previously differed in what the app
was allowed to do.
