RedLine already answered what your agents cost. This beta adds what they are doing, and marks the menu bar when one of them is blocked waiting on you.

### Added: the agent fleet

Claude Code keeps a live registry of the sessions running on this Mac, one small record per
session, deleted when the session exits. RedLine now reads it and lists those sessions in the
dropdown under **Agents**, between the rate limits and the volume: session name, the folder it
is working in, its status, and how long it has been in that status.

The rows sort waiting first, then busy, then idle, and inside each state the one that has been
there longest floats to the top. So the session that has been sitting on a prompt for an hour
is the first line you read. When any session is waiting, an amber dot appears ahead of the
menu bar readout, counted once there is more than one. Busy never earns a badge; a badge that
is always lit says nothing.

Each row opens on what you can do with it: raise the terminal or editor the session is running
inside, copy its folder path, or open the same session on claude.ai. That last one is the only
link between the local and the cloud view that Claude Code hands out, so it is worth the click
it takes to wire. Under those sit the PID, the Claude Code version and the entrypoint, for
when a row is not the session you assumed.

Because the desktop app and the IDE extensions run the same binary, they register in the same
place, so this covers those sessions too without any extra work. Cloud sessions and sessions
on other machines are deliberately out: there is no public API for them, and the only routes
are a headless bridge session or a private endpoint. Codex has no equivalent live registry at
all.

Switch it off under **Settings > Show Running Agents**, or with `agentFleet` in the config.

### Changed: how RedLine notices

A session starting or exiting changes the registry directory, so a directory watcher sees it.
A status change rewrites the record in place, which never touches the directory, so every live
record is watched individually as well. That is what makes the badge appear when a session
blocks rather than up to half a minute later. A slow sweep sits under both, because a killed
session writes nothing at all and its leftover record has to be reaped on a timer.

Nothing here writes to `~/.claude`. The key files that sit beside the records are never opened,
and the messaging sockets the records name are never connected to.
