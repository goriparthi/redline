The rate limit note now tells an idle Claude Code apart from a feed that is actually broken, and RedLine is a macOS only project again.

### Fixed: a quiet feed no longer reads as a fault

When no Claude Code session has run for a while, every window in the usage sidecar expires and RedLine is left with no percentage to show. The menu filled that gap with "Waiting for Claude Code to report usage", which reads as though the feed were broken or had never been wired up. It is neither. It is just quiet, and it fills itself in the moment you start a session.

The note now separates the two cases. A feed that has reported before, which RedLine can tell because the sidecar is still on disk, reads "No Claude Code activity since the last reset". A feed that has never written anything still reads "Waiting for Claude Code to report usage", because that one really can mean the setup did not finish. The menu bar tooltip carries the same wording, so hovering answers the question without opening the menu.

### Changed: macOS only again

The cross-platform port has been removed. The Windows shell, the platform and UI modules that existed only to support it, the vendored SQLite amalgamation and the PowerShell feeders are all gone, and the tree is back to the shape 0.8.3 shipped from. This changes nothing about the macOS app you are running. The Windows build was never released, so there is no one to migrate and nothing to reinstall.

The reason it is worth mentioning at all is what it means for the code: every file that had grown a platform branch has lost it, and the core is once again written against one operating system rather than three.
