RedLine now says when a limit will run out rather than only how much of it is gone, keeps its own history so the charts stop getting shallower, tells you without being looked at, reads what your transcripts say about your setup, and answers value questions on hover.

### Added: time to limit, not just percent used

Every window that has run long enough now carries a rate. The menu, the dashboard rails and
the CLI say whether the cap arrives before the reset does, and how long is left at the
current pace. Where readings have been recorded inside the same window the rate is measured
by differencing them; otherwise it is the window's own average so far, and the tooltip says
which of the two it got. The minimum span between readings scales with the window, so a
weekly rate needs hours of readings rather than minutes and a session window still catches a
burst. The rails also carry a thin marker showing where the clock has reached, so being ahead
of pace is something you see rather than something you calculate.

### Added: notifications, off until you ask for them

**Settings ▸ Notify at Thresholds** posts a notification when a window crosses your amber or
signal percentage, when it is about to run out before it resets, when it reaches the cap, and
when it rolls over and capacity comes back. Each event fires once per window instance, and
never from a stale reading: a percentage nobody can vouch for is not news. macOS is asked for
permission when you switch the setting on rather than at first launch.

### Added: history that outlives the transcripts

Claude Code prunes its own projects directory, so a chart built only from what is still on
disk gets quietly shallower every week. RedLine now rolls each day up into
`~/.local/share/redline/history` as it polls, keyed by UTC day, provider and model. The rule
that matters is that a smaller scan never overwrites a fuller one, so a pruned transcript
cannot erase what was already recorded. The dashboard shows what has been kept; the setting
is **Keep Local History** and it is on by default.

### Added: a bundled command line tool

`Redline.app/Contents/MacOS/redline status --json` answers with the current windows, their
pace, and today's and this week's totals, every figure labelled with where it came from.
There is also `findings` and `history`, the latter with `--csv`. Exit codes are part of the
contract: 0 fine, 10 near a limit, 11 at a limit, 20 nothing to report, 30 no data. Nothing
in the tool fetches anything; it reads what the app already published.

### Added: the usage sidecar, written as well as read

RedLine now publishes its windows to `~/.local/share/redline/usage-snapshot.json` in the
shape ClaudeHUD and claude-monitor already read, so a status line or a tmux strip can take
this reading instead of every tool racing for the same source. It reads one too: point
`externalUsagePath` at another tool's sidecar and it becomes a fallback for when RedLine's
own feed is quiet. Local files, no network, and the published file is removed when you turn
the setting off.

### Added: setup findings

A new dashboard panel reports what your transcripts say about how Claude Code is set up: MCP
servers configured but never called, skills and agents and commands defined and never
invoked, files read three or more times inside one session, and memory files large enough to
be worth knowing about. Findings say whether their numbers were counted or estimated, and a
finding with nothing honest to put on it carries no dollar figure at all. The scan runs in
the background at most every six hours, and `redline findings` runs it on demand.

### Added: hover readouts on every chart

Point at any day or hour and a readout names each provider's figure for that bucket and the
total, snapped to the nearest bucket so the gap between two bars is still answerable. The
charts were good at shape questions and useless for value questions; this is the value
question.

### Changed: every number can name its source

Limit windows now carry where they came from, and the exports say so: `official` for what
Claude Code and Codex report themselves, `experimental` for the undocumented usage endpoint,
`local_estimate` for anything priced here. Cost figures are marked partial rather than
unknown when only some models had a price, which is the same thing the menu's `+` has always
meant.

### Fixed: a diagonal band across the cost chart

The estimated cost chart drew a straight band from the first day at the left to the last day
at the bottom right, over the top of the real series. The area fill carried a flat colour and
no series identity, so Charts treated every provider's points as one series and closed the
shape from the last Claude day back to the first Codex day. It looked like data and was not.
The fill now carries the series, unstacked to match the lines drawn over it.

### Changed: the dropdown and the findings panel

Pace now rides on the same row as the percentage instead of sitting on its own line next to
the provenance note as if the two were a pair. Findings have a coloured rule down the side, a
pill for the kind, evidence in two aligned columns rather than one run-on line, and the
counted or estimated label sitting next to the figure it qualifies. Prose is held to a
readable measure instead of running the full width of the window. A rescan that finishes
inside the same minute no longer looks dead: the button becomes a spinner for the duration
and the timestamp carries seconds.
