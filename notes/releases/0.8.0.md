The interface is rebuilt on one design system, every provider now carries its own mark, settings moved into a real window, and two bugs that quietly reverted your choices are fixed.

### Changed: one design system instead of styling per screen

Every colour, space, corner radius and text style now comes from one place, and the dashboard,
the menu, the setup window and the widget all read from it. Before this, a panel picked its own
font sizes and its own greys, so the same idea looked slightly different depending on which
screen you were on.

The practical difference is that light mode is now a real design rather than dark mode with the
colours flipped. Cards sit on warm paper with hairline borders, and the accents run darker so
they hold their contrast against white.

Status is no longer carried by colour alone anywhere. Every state has its own shape as well as
its own colour, so healthy, approaching, at the limit, stale, stopped and unchecked stay
distinguishable in greyscale and to a colour blind reader. The words are there too.

### Added: the provider marks

Claude, Codex and Ollama are now identified by their own marks rather than by three shapes
RedLine invented. The marks stay monochrome and unaltered; the colour lives on the chip, dot,
rail or chart series around them, and the provider's name always sits beside the mark. The
licences and notices are in the app under **Settings ▸ About**.

The provider colours were picked against numbers rather than by eye: contrast on every surface
in both appearances, one lightness band so no provider shouts over the others, enough hue
separation to tell them apart, distance from the RedLine red so a provider colour can never be
mistaken for a warning, and separability under all three kinds of colour blindness. Two
palettes were rejected before one passed.

### Added: an overview, and a card per provider

Opening the dashboard used to start with five totals tiles, which answer "how much" when the
question you actually have is "is anything about to stop me". The window now opens on the
nearest limit across every provider, then a card each for Claude, Codex and Ollama carrying the
percentage, what is left, when it resets, a fortnight of shape, and volume with cost.

When a window crosses your configured threshold, or is going to run out before it resets, that
is stated in words at the top before any chart. Nothing is shown when nothing is true, and at
most three are listed with the rest counted, because a banner that is always lit says nothing.

A card that has no figures says why instead of going blank. There is a real difference between
a tool that is not installed, one you switched off, one whose server is not running, and one
that simply had a quiet fortnight, and the card now names which. A stopped Ollama used to read
as "no usage in this range", which looks like a quiet day rather than a server to start.

Clicking a card opens that provider on its own, with current usage, remaining capacity, reset
time, where the figures came from and how fresh they are. A metric that cannot exist says so:
Ollama runs on your Mac, so it reports no rate limit, and the card says that rather than
showing a zero.

### Added: a settings window

Settings had grown longer than the readout the dropdown exists for, and a flat column of
toggles is not somewhere a threshold or a privacy choice can explain itself. **Settings ▸**
now opens a window with six sections: Providers, Refresh and Monitoring, Limits and Alerts,
Appearance, Data and Privacy, and About. Every preference carries the reason it exists next to
it rather than hiding it in a tooltip.

Two things are worth knowing. The thresholds are now editable, and they drive the rails, the
cards, the menu bar colour and the notifications together, so those four can no longer
disagree. And **Data and Privacy** lists the only two settings that make a network request in
one place, rather than leaving you to work that out.

Everything the old submenu did is in the window, and the preferences that do more than store a
value still run the same code they always did. Switching alerts on is still the moment macOS is
asked for permission; switching the agent list on still starts its watchers.

### Fixed: setup quietly reverting your Claude limits choice

If you had the usage feed installed and later switched to the Claude Code CLI's token, then
reopened the setup window, it showed the feed selected instead of the token. Pressing **Start**
then wrote your choice back to off. Installing the feed never uninstalls itself, so its being
on disk was being read as what you wanted now, and it outranked the decision you had actually
made.

An explicit credential choice now outranks whatever happens to be installed. This is the bug
behind settings appearing to reset themselves after a restart.

### Fixed: a rejected sign-in renewal retried forever

When RedLine's own browser sign-in failed to renew, only one specific error was treated as
final. That endpoint answers in a different format, so every other rejection was retried on the
next poll, and the one after that, indefinitely. RedLine stayed "signed in", the percentages
never came back, and nothing offered you a way to sign in again.

Now only a lifted rate limit, a recovered server or a working network are retried, since those
are the only three things that can make the same request succeed later. Anything else clears
the dead sign-in so the app offers **Sign In** instead of grinding away at a grant that is
gone. The error text you see is a sentence rather than a pasted server payload.

Token requests are also sent the way the OAuth spec specifies, with the previous format kept as
a fallback and whichever works remembered. That part is a suspected cause of one report rather
than a confirmed fix, so it is worth saying plainly: if renewal was failing for you, this may or
may not be why.

### Install

    brew install --cask ./Casks/redline.rb

Or download the DMG below. Requires macOS Sonoma or later. Nothing changed since
0.8.0-beta.1, so if you are already on that build this is the same app with a stable
version number.
